1. PRESENTATION GENERALE
-----------------------
HUB DIGI est le hub interne multi-departements de Digi Com & Technologies
+ un portail client externe.

- Le HUB (agents internes) : https://hub.digicom.ml/
  API : https://hub.digicom.ml/api/v1/
  Admin Django : https://hub.digicom.ml/admin/
  Doc API OpenAPI : https://hub.digicom.ml/api/docs/
- Le Portail Client : https://hub.digicom.ml/espace/:slug/:code
  Exemple : /espace/orange-mali/4821 (slug societe + code a 4 chiffres).
  Route historique /espace-client redirige vers /espace.
- Le Tracker JS : https://hub.digicom.ml/static/tracker.js
  Script a coller sur les sites clients pour remonter les bugs JS
  automatiquement.

Objectifs :
- Un Super Admin cree les comptes et assigne Departement + Poste.
- Chaque departement a son espace et ses outils metier.
- Le Super Admin voit tout.
- Le client suit ses projets, factures, recus, tickets, bugs sans appeler.
- Factures / recus / BDC / BDL / rapports PDF generes automatiquement.
- Traçabilite via AuditLog (visible /admin/ en lecture seule).

2. ROLES ET PERMISSIONS
----------------------
Roles geres (JWT contient role, department_id, poste_id) :

- super_admin : acces total. Cree/desactive les users, assigne Dept+Poste,
  configure les mails, voit les logs, valide tout. Seul a /parametres.
  Peut previsualiser n'importe quel portail client via slug+code.
- admin (Administration / Secretariat) : transverse hors technique/finance.
  Dashboard global, clients, conges (validation), boite tickets,
  courriers, reunions/PV, e-mails. PAS d'acces aux onglets internes
  Dev / Com / Finance / Juridique.
- chef_com / membre_com : campagnes, calendrier editorial, medias clients.
- chef_dev / membre_dev : projets, taches Kanban, bugs, deploiements.
  Seul le chef a les droits d'edition sensibles (crayons reserves).
- chef_rh / membre_rh : employes, conges, recrutement, pointage QR.
- chef_juridique / membre_juridique : contrats, litiges, echeances.
- chef_finance / membre_finance : devis, factures, recus, depenses, paie,
  fournisseurs/achats.
- client : ne voit que ses propres donnees (filtre where client_id = me).
  Accede uniquement a /espace/:slug/:code. Ne voit pas le dashboard interne.

Regles :
- Poste toujours rattache a un Department (ex: Dev -> Chef Projet, Dev Front).
- Chef valide/assigne, Membre execute.
- Frontend : sidebar filtree (src/lib/acces.js) + routes gardees (RequireRole).
  C'est un garde-fou, pas la securite reelle.
- Backend : permissions DRF par role + filtres automatiques. Le backend ne
  fait jamais confiance au frontend.

Client interne (est_interne, MAJ 05/10/2026) :
- Digi Com elle-meme est geree comme client dans le hub (case a cocher
  + detection auto "digicom" dans /clients/nouveau, badge Interne liste/fiche).
- Aucun compte role=client cree pour elle, aucun /espace, login + portail
  refuses cote backend.

3. CONCEPT CENTRAL : FICHE CLIENT 360°
--------------------------------------
Route front : /clients/:id
Route API : /api/v1/clients/:id/overview/

Tout objet metier a une FK client. Les vues departements filtrent par
?client_id=. La fiche regroupe en onglets :

  username/mot de passe generes a la creation (affiches en fiche, transmis

- Com : campagnes liees, calendrier editorial filtre client, assets a valider.
- Finance : devis, factures, recus PDF, solde impayes, bouton relancer.
- Juridique : contrats signes, echeances, documents.
- Tickets & Mails : historique tickets + mails envoyes/recus.
- Documents : tous fichiers lies.

----------------------------------------------

b) Courriers (/secretariat/courriers) :
   - Numerotation COUR-AAAA-NNNN.
   - Workflow : brouillon -> envoye/recu -> traite -> archive.
   - Papier a en-tete officiel + cachet Secretariat importe en Parametres,
     sans mention "sortant" sur le document, signature manuscrite apres
     impression, bouton Imprimer / PDF navigateur.

c) Decharges (/secretariat/decharges) :
   - Registre DCH-AAAA-NNNN (provenance, objet, montant optionnel,
     date de reception, commentaire).
   - Scan uploade compresse cote serveur (JPEG 1600px q70, poids affiche).
   - Suppression reservee super_admin/admin.

d) Reunions + PV (/secretariat/reunions) :
   Statuts : Planifiee -> PV en redaction -> Cloturee.
   - Creation -> convocation auto par mail a chaque participant (date, heure,
     lieu + ODJ, via admin@digicom.ml) + notif in-app. Toute modif date/lieu/
     participants renvoie une mise a jour.
   - Ordre du jour modifiable uniquement au statut Planifiee. Fige des le
     passage en "PV en redaction".
   - PV redigeable uniquement en "PV en redaction". Decisions avec responsable
     + echeance obligatoires.
   - Decision -> tache Kanban assignee (POST /reunions/:id/decisions/:id/
     convertir/ {project_id}), responsable repris comme assigne, lien retour.
   - Cloture -> diffusion auto du PV par mail + verrou total (lecture seule).
   - Archivage global, validation niveau 1 (conges, factures brouillon,
     contrats).

7. DEVELOPPEMENT (/projets, /dev/*, /bugs) — v1.4 Jira
-----------------------------------------
- Projets : client FK, type (site_web, app_web, app_mobile, autre), statut,
  deadline, jalons, % auto depuis taches, repo_url, envs prod/staging,
  notes de deploiement. Onglets detail : Kanban / Sprints / GitHub (+ Backlog).
- Taches (Jira §1) : reference serveur TASK-AAAA-NNNN (compteur atomique/an,
  retro-remplie), estimation_points (1,2,3,5,8,13…), estimation_heures,
  priorite basse|normale|haute|critique (defaut normale), done_at auto
  (renseigne en done, vide a la reouverture). Temps passe = reel, distinct.
  Permissions : estimation/priorite/sprint modifiables par chef_dev/super_admin
  uniquement (403 API + champs desactives pour membre_dev) ; membre_dev deplace
  et saisit son temps. Filtres ?priorite= ?assigne= ?statut= ?sprint=, tri
  priorite, recherche reference+titre. Carte Kanban : reference, badge
  priorite, estimation, compare estime/passe, flag +sprint, section
  Developpement (liens Git + copier branche feature/TASK-…-slug).
- Sprints & backlog (Jira §2, /dev/backlog + onglet Sprints) : Sprint (projet,
  nom, objectif, debut/fin, planifie|actif|termine, points engages/termines
  figes, demarre/termine_le). Un seul actif/projet (400 sinon). Backlog =
  taches sans sprint non terminees (tri priorite puis creation). Demarrer fige
  les points (somme estimations, sinon nb taches) ; terminer fige les points
  termines et deplace les ouvertes vers sprint_cible ou backlog (ecran de
  cloture). Ajout en cours de sprint visible (+sprint via sprint_added_at).
  Kanban : selecteur de sprint (defaut actif) + bandeau nom/objectif/dates/
  jours restants/progression points.
- Rapports (Jira §3, calcul a la demande, sans Beat) : GET /sprints/:id/rapport/
  (serie par jour ouvre lun-ven {date, restant_ideal lineaire, restant_reel via
  done_at}, totaux engages/termines/taches/ajoutes, temps estime vs passe ;
  sans estimation = comptage taches) + GET /projets/:id/velocite/?n=6 (N
  derniers termines + moyenne). Frontend : burndown SVG ideal vs reel,
  histogramme velocite, carte Pilotage « Sprints actifs » (chef_dev/super_admin).
  Export PDF ReportLab : non fait (optionnel).
- GitHub entrant V1 sans OAuth (Jira §4) : convention TASK-/BUG-AAAA-NNNN
  insensible casse dans commits/PR/branches. Project.github_repo (deduit de
  repo_url), github_webhook_secret (token_urlsafe 32, jamais renvoye, affiche
  une fois a la regeneration chef_dev/super_admin), github_auto_statut (defaut
  False). Modeles LienGit (task ou bug exclusif, commit|pull_request|branche,
  statut_pr ouverte|fusionnee|fermee) + LivraisonWebhook (idempotence).
  POST /api/v1/github/webhook/<project_id>/ public throttled : HMAC SHA-256
  X-Hub-Signature-256 compare_digest (403 sinon), corps ≤ 1 Mo, idempotence
  X-GitHub-Delivery (200 sans retraiter), depot verifie, ping 200, push/PR
  traites (autres 202), rattachement meme projet uniquement. Auto (si option) :
  1re PR ouverte a_faire→en_cours, fusion→review, jamais done ; bugs : liens
  seuls. Notif in-app chef_dev/super_admin a la fusion (+ AuditLog best-effort).
  Frontend : onglet GitHub (repo, URL webhook a copier, secret une fois,
  regenerer, mode d'emploi, interrupteur auto, 20 dernieres livraisons),
  section Developpement tache/bug, bouton copier branche.
- Suivi transmis au client (section "Suivi client" dans ProjetDetail) :
  jalons = grandes etapes de validation convenues (pas les taches Kanban
  internes), livrables = fichiers finalises remis au client. Visible dans
  /espace/:slug.
- Bugs remontes visibles dans l'espace projet (onglet Bugs) + conversion
  en tache en 1 clic ("Convertir en tache" -> Task liee) + section
  Developpement (liens Git).
- Si type site_web/app_web -> PROJECT_KEY (digi_pub_xxx) + snippet tracker
  hub.digicom.ml/static/tracker.js avec bouton copier (voir section 12).

d) Pointage QR dynamique (/pointage + /rh/pointage + /rh/rapports) :

13. BUG TRACKER VIA tracker.js
------------------------------
Uniquement si projet Dev type=site_web | app_web.
- A la creation projet web -> ProjectTrackerKey (public_key=digi_pub_xxx) +
  snippet affiche avec bouton copier :
  <script src="https://hub.digicom.ml/static/tracker.js" data-key="digi_pub_xxx"></script>
  (l'endpoint de report suit le domaine du src, fichier servi en cache long,
  bumper ?v=N a chaque MAJ).
- tracker.js (vanilla ~3 Ko, aucun widget visible, capture 100% auto) :
  window.onerror + unhandledrejection (message, stack tronquee, URL, userAgent,
  viewport) + ressources en echec en phase capture (script/CSS/image/chunk
  introuvable, tag + URL fautive).
- Gravite auto cote script : haute = site partiellement casse (chunk/script/
  CSS en echec, failed to fetch, erreur chargement dynamique, MIME),
  moyenne = reste. Repli backend moyenne si gravite absente/invalide.
  La Dev requalifie dans le HUB.
- POST /api/v1/bugs/report/ {key, message, stack, url, meta, gravite?} avec
  throttle bugs (30/min). Cle invalide -> 403.
- Modele BugReport (numero BUG-YYYY-#### auto, project FK, titre, description,
  gravite transmissible, statut nouveau/confirme/en_cours/corrige/rejete,
  assigne, meta_json).
- Visible dans /dev/projets/:id onglet Bugs + portail client (ses bugs +
  statut). Bouton "Convertir en tache".
- Notif a chaque bug : in-app (cloche) Chef Dev + Super Admin, + Administration
  et mail dev@ si critique/gravite haute.
- Alerte mail systematique au responsable (toutes gravites) : BUG_ALERT_EMAIL
  (defaut abdoulaye208.mac@gmail.com, reglable via backend/.env), jamais
  bloquant (fail_silently). Couvre le cas hors-ligne : le mail attend dans
  la boite, contrairement a la cloche.
- Push web avec TTL 7 jours : le service push conserve le message si l'appareil
  est hors-ligne (navigateur ferme) et le livre a la reconnexion. Frontend :
  ecouteur `online` dans la Topbar -> rechargement aussitot des notifs + toast
  « Connexion retablie ». Cartes Dépôt/Tracker responsive (break-all, wrap).
- V1 : erreurs JS + feedback manuel. V2 prevue : source-maps, screenshots, perf.
- Secu : cle publique exposable, allowed_origins stockee par projet (controle
  origine non enforced - a durcir). Mention consentement a ajouter cote site
  client.
